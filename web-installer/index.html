LoRa Mesh — Pico 2 W Web Installer

Static page, no build step. No sudo, no keys leave the board. Flashing is a UF2 file copy onto the BOOTSEL mass-storage volume.

Private secure mesh is the default. A Meshtastic-compatibility mode, if ever offered here, would be labelled insecure — this installer never enables it.

1 · Pick a firmware image

Default: radio-secure. The radio-free image is a bench diagnostic only (pairing/contacts/time work, RF returns RADIO_UNAVAILABLE).

Releases are defined in releases.json next to this page. Each entry has a file URL plus SHA-256 so you can verify the download before copying it to the board.

2 · Enter BOOTSEL (hold-button flow)

  1. Unplug the Pico 2 W.
  2. Hold BOOTSEL, plug USB back in, then release.
  3. A mass-storage volume appears named RPI-RP2 (some hosts show RP2350).
Not probed yet.

3 · Copy the UF2

Option A (automatic, Chromium): download the UF2 below, then Pick BOOTSEL drive… and press Write UF2 to drive. Option B (every browser): drag the downloaded .uf2 file onto the RPI-RP2 drive in your file manager. The board reboots itself when the copy finishes.

4 · Set up meshctl + verify

One-time host setup (creates the venv, installs meshctl):

git clone <repo-url> LoRa_Mesh_Handoff
cd LoRa_Mesh_Handoff
python3 -m venv .venv
.venv/bin/python -m pip install -e ./host

Then download the guided post-flash script and run it (replace /dev/ttyACM0 with your port):

scripts/mesh-setup.sh
bash scripts/mesh-setup.sh /dev/ttyACM0 --label A

Expect JSON containing (values vary per board):

{
  "board": "pico2w",
  "image": "radio-secure",
  "radio_available": true,
  "provisioned": false
}

A radio-free diagnostic image instead reports "image": "radio-free" and "radio_available": false with no radio_version field. Identify boards by USB serial plus this status output — never by ttyACM number.

5 · WiFi for the TCP transport (after first flash)

The radio-secure image serves the same newline-JSON wire on TCP 7777 once it joins your network. The passphrase never appears in output or logs, and the board joins live with no reboot:

.venv/bin/python -m meshctl --port /dev/ttyACM0 wifi status

Then talk over WiFi instead of USB:

.venv/bin/python -m meshctl --transport tcp --tcp-host 192.168.1.10 status

Find the board's IP from your router/DHCP list. `wifi forget` clears the stored credential. Secrets stay in board flash; this page never sees them.

6 · Updates (OTA note)

There is no over-the-air firmware update in this release: updates ship as signed UF2 images flashed over USB BOOTSEL exactly like the first install (pick the new release above, copy, verify with meshctl status). The WiFi TCP transport carries only the newline-JSON CLI wire — it cannot replace firmware. A future OTA path would need image signatures + rollback + a second flash bank, none of which exist on this layout; do not treat the TCP port as a firmware channel.

RP2350 UF2 limits

  • There is no WebSerial / esptool path for the RP2350. ESP32-style ROM-bootloader flashing over a serial port does not exist here; the only browser-visible route is the BOOTSEL UF2 mass-storage volume, optionally enumerated read-only via WebUSB (2e8a:000f BOOTSEL, 2e8a:0001 app).
  • Browsers cannot mount/unmount volumes and cannot reboot the board into BOOTSEL themselves — the hold-button step is physical and mandatory.
  • WebUSB cannot claim the BOOTSEL mass-storage interface; detection is informational only. The actual write uses the File System Access API (Chromium) or a manual file-manager copy (everywhere else).
  • Firefox/Safari have no File System Access directory-write path, so only download + drag-drop works there.
  • SHA-256 is checked in-page after download when the manifest carries a hash; the browser never handles keys or provisioning secrets.

Serve this directory statically (e.g. python3 -m http.server). File System Access writes need a secure context (https:// or http://localhost).
